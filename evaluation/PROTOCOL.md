## 2. Offline vs online (strictly separated)
- **Offline** (`evaluation/offline_rank.py`, evaluator only): from one full `snapshot()`, every candidate is executed in a branch
  (`restore` → reseed env RNG → segment → settle with zero actions until |obj_vel|<1e-3 or 20 steps). Outcome = settled goal error
  [m] + success. Gives true candidate ranking, oracle, headroom. Fixed-candidate oracle = **diagnostic upper bound, not a method**.
- **Online** (E2/E3): only the chosen action/probe is executed; after a probe the episode continues from the actual new state; no
  `restore`, no reset, no evaluator queries. Audited by `audit.online_accounting` (obs continuity record-to-record, budgets, time).
- Stochastic continuation (variant with action_noise=0.02): common random numbers — rep seed r is identical for every candidate
  (offline) / every method (online). Oracle selection uses rep seeds {11,12,13}; reported oracle value uses disjoint {21,22,23}.
  Online stochastic variant: 3 reps, env seed = `seed*10+rep`, same for all methods. Deterministic primary: env seed = test seed,
  action_noise=0, obs_noise=0.

## 4. Experiments and pre-registered gates/criteria
**E0 (env qualification; 12 e0 states × {mu_lo,mu_mid,mu_hi} and × neg_control)** — PASS only if all of:
- G1 replay: `audit.snapshot_exactness` has no issues on PushEnv with action_noise 0 and 0.05 (obs + full snapshot bit-identical,
  same instance and fresh instance, RNG included, no aliasing).
- G2 leakage: static scan hits all reviewed benign; runtime `TrackedHidden` + `GuardedPolicy` 0 violations on ≥1 episode per method.
- G3 best action changes with condition: with REF8 offline oracle, oracle index differs between mu_lo and mu_hi in ≥6/12 states,
  and mean cross-condition regret (error under mu_hi of mu_lo's oracle minus mu_hi oracle error) ≥ 0.02 m.
- G4 identifiability: for ≥1 of the 3 probes (A4 `probe_set`: tap_fast, push_slow, retreat; 5 steps each), the visible feedback
  (obj displacement and obj_vel at probe end) separates every pair of test conditions by > 1e-3 m (deterministic) in ≥11/12 states,
  and nearest-centroid condition classification from feedback ≥ 90% under action_noise=0.02 (3 reps, centroids from e0 reps
  {11,12,13}, classified reps {21,22,23}).
- G5 negative control (e0_neg × 3 conditions, STRIKE54): the oracle index is identical across conditions, or one action is within
  0.005 m of the per-condition best under all conditions, in ≥ 9/12 states.
  If G5 fails, the negative control is declared NOT qualified (E3 negative-control claims are then void).

**E1 (headroom; 20 e1 states × 3 test conditions × REF4 and A5 4-candidate library)**: report per state/condition true errors,
spread (max−min), all-fail fraction, oracle (select/eval reps split), each scorer's pairwise accuracy, top-1 regret, top-1 correct,
candidate diversity. Headroom exists if mean oracle-vs-median-candidate gap ≥ 0.01 m. Stochastic variant: reps as §2 (3+3).

**E2 (closed-loop pilot; 40 test states × 3 test conditions = 120 paired episodes per method, deterministic primary)**:
- Budget (identical for all methods): ≤60 control steps total INCLUDING probes, ≤10 probe steps (= two 5-step probes), DT 0.1 s → ≤6.0 s physical time;
  termination ∈ {success, out_of_bounds, timeout, budget}. success = env success (in goal, at rest) before budget end.
- Decision records per shared `DecisionRecord`; `wall_time_s` keys propose/predict/update/score/probe reported separately.
- Throughput/logging smoke checks must use **val** states, not test. Each method config is hashed and timestamped before its first test
  run; any config change after first test read is flagged as test-set tuning in the audit log.
**E3 (necessity / negative control; from E2 records + runs on test_neg (40) × 3 conditions)**:
adapt vs same-probe-no-update; WM route vs A9 direct-history baseline; probe vs no-probe; probe rate & probe steps under neg control.

## 5. Metrics (definitions in `evaluation/metrics.py`)
- success rate; goal error = |obj−goal| at last record (m); total interaction = executed control steps (probe + task); probe steps;
  physical time = steps × 0.1 s; compute time per category (wall clock, shared 8-CPU box under load → indicative only).
- pairwise ranking accuracy vs offline truth: true tie if |e_i−e_j| ≤ 1e-3 m → pair excluded (count reported); predicted tie
  (|Δs| ≤ 1e-12) on non-tied pair = 0.5.
- top-1 selection regret = e(chosen) − min e; tied scorer max → mean over tied set. top-1 correct = chosen within 1e-3 m of best.
- endpoint error = |predicted endpoint − true segment endpoint| (offline truth, eval rep seed 21).
- Every metric reported overall AND per hidden condition.

## 6. Uncertainty and comparisons
- Unit of resampling = init state (cluster). Cluster bootstrap B=2000, seed 0, 95% percentile CI. Conditions, reps and candidates of one
  init state are never counted as independent samples.
- Method comparisons are paired on (init_state_id, hidden_condition_id, rep); per-cluster differences bootstrapped. Unpaired keys are
  reported and make the comparison invalid.
- Primary comparisons (3, exploratory, no multiplicity correction, pilot → no "significant improvement" claims):
  P1 adapt vs same-probe-no-adapt; P2 WM route vs direct-history baseline; P3 best probing method vs no-probe. Metrics: goal error,
  success. A difference is "supported in this pilot" only if the 95% cluster CI excludes 0 for the overall paired difference.
